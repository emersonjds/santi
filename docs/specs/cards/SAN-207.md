# SAN-207 — Issue links in exports, backups and restore

No UI; the account export, scheduled backups (SAN-205) and `POST /api/projects/restore` (SAN-99).

## Scope

- Each project of `GET /api/me/export` and each backup file gains `links`: `{ source, target,
  relation }`, keys as `KEY-N`, the relation as seen from `source`. Files without `links` still
  restore.
- Restore recreates them; the response shape does not change (skipped links are `problems`).

## Export rule

- Read as the exporting member, in one REPEATABLE READ, read-only transaction with the issues and
  comments, so links never name an issue the file lacks.
- A link of an issue of the project is exported when the exporter can open its other issue (a
  member of that project, not trashed). Outgoing links are written from the source; incoming
  links from other projects are written from this project's side with the relation seen from
  here (`is_blocked_by`, …). A link between two issues of the project is written once, from its
  source.

## Restore rules

- `source` must be an issue of the file; a target in the project must be one too; a target in
  another project is resolved by its live or previous key. The file is refused (422 naming
  `links[i].…`) otherwise, or when an issue links to itself, or past 500,000 links.
- A link is inserted when the restorer can open both ends and neither project is archived;
  inverse relations are stored forward; a link already there is left alone. The resolved ends
  are held with `FOR KEY SHARE` until the commit, so a concurrent delete cannot break the insert.
- Each other link becomes a problem, `issue_key` = its source:
  - `Link {SRC} {relation} {TGT} skipped: you cannot open {TGT}.`
  - `Link {SRC} {relation} {TGT} skipped: the project of {TGT} is archived.`
  - `Link {SRC} {relation} {TGT} skipped: an issue cannot link to itself.` (ends that resolve to
    one issue)
  - `{relation}` with spaces (`is blocked by`).
- Problems stay at most 100: when skipped links do not fit, the last slot is
  `{N} more links skipped.` with the project key as `issue_key`.

## Backups

- Each file is read through one member of the project, an admin first, so it holds only links
  to projects that member can open. Restoring the second of two linked projects brings their
  links back once both files contain them.
- A target key is the key at export time: if that project was purged and another later took the
  key, the link attaches to the new project's issue for a restorer who is a member there.
- Links whose ends the file lacks (concurrent writes) are dropped; beyond 500,000 the file keeps
  the first 500,000 and logs how many it left out, instead of skipping the project.
