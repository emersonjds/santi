# SAN-199 — The web app in five languages

Owner, 2026-11-18: the web app speaks English (default for every account, no browser detection),
Español, 中文（简体）, Português (Brasil) and Português (Portugal), chosen in /account Preferences next
to Theme. Typed dictionaries with English as the key source, each language loaded on demand, no heavy
runtime (D39: at most +2 KB initial JS per route). Landing, legal pages, CLI and MCP are later cards.

## Context

- Preferences pattern (D54, `docs/specs/cards/SAN-93.md`): `app_user.theme text NOT NULL DEFAULT
  'system' CHECK (...)` (migration 0028), `User.theme`, `PATCH /api/me { theme? }`, text-backed enum
  through `text_type!` in `crates/santi-types/src/lib.rs`. Web: `web/src/shared/lib/theme.ts` mirrors the
  choice to localStorage, `web/public/theme.js` applies it before first paint, `AppShell` re-applies
  `user.theme` once `/api/me` loads, `features/account/theme-control.tsx` applies at once and reverts on a
  failed save.
- No i18n library is installed; none is needed. The SPA has ~285 source files with copy; a rough count
  finds 840+ literals (~17 KB raw, ~6 KB gzip) before aria-labels and placeholders, so a full English
  table is ~10–12 KB gzip. Most of it lives today in lazy route chunks.
- Size limits (`web/.size-limit.js`, each ~3 KB above the measured size): `/login` 127 KB, `/account`
  145.5 KB, backlog 165 KB (closest to the 170 KB cap). A single English table in the entry would add
  the copy of every other route to each first visit: it fails D39.
- Dates: `shared/lib/format-date.ts` takes a `locale` argument that every caller leaves undefined (the
  browser's). `entities/issue/time-ago.ts` pins `'en'`; `shared/lib/sprint-dates.ts` and the rich-text
  counter pin `'en-US'`. The zone is the account's (SAN-93/SAN-197).
- Errors (D24): `type` is a stable slug (`urn:santi:error:<slug>`); `detail` and `errors[].message` are
  English. About 10 places show `detail` (`shared/lib/show-problem.ts`).
- No webfont: Tailwind's `font-sans` is the system stack, so Chinese already renders in the system
  CJK font; `<html lang>` picks the right glyph variants.

## Scope

- Server: `app_user.language` (default `en`), `User.language`, `PATCH /api/me { language? }`, 422 on an
  unknown tag; erasing an account resets it to `en`. OpenAPI regenerated.
- Web: the i18n core, the Language control in Preferences, dictionaries for es, pt-BR, pt-PT, zh-CN,
  every screen of the SPA translated batch by batch, dates and numbers in the chosen language, API
  errors translated by `type`.
- Out: landing, legal pages, CLI, MCP, server error text (stays English), a separate date-format
  preference, a language picker on the sign-in screens.

## Open questions (panel)

| # | Question | Options |
|---|---|---|
| 1 | Where the switch lives and its control | (a) native select in Preferences between Theme and Time zone; (b) segmented control like Theme; (c) the searchable picker of Time zone; (d) a radio list |
| 2 | Fallback for a string without a translation | (a) English for that string; (b) the key itself; (c) refuse to offer a language until every string has a translation |
| 3 | Before `/api/me` answers | (a) render English, switch when it answers (flash); (b) mirror the last choice in localStorage and hold the first render until that language's chunk loads, then follow `/api/me`; (c) a pre-paint script like `theme.js` |
| 4 | Sign-in, sign-up, reset and join screens (no account yet) | (a) always English; (b) the last language used on this device (localStorage), kept after sign-out; (c) a language picker on those screens |
| 5 | Dates and numbers | (a) follow the language (`Intl` locale = language), zone stays the account's; (b) stay on the browser locale; (c) a separate date-format preference |
| 6 | How tests assert copy | (a) tests keep asserting English (default language), a few cases switch language; (b) assert keys; (c) snapshot per language |

Architect challenge: dictionary format (plain objects + tiny `t()` vs a library), bundle split,
migration, incremental rollout without one huge diff, a guard against raw literals, tests.

## Decisions

Panel 2026-11-18 (one agent: product, ux, ia votes + architect), unanimous unless marked.

| # | Winner | Trade-off |
|---|---|---|
| 1 | (a) `NativeSelect` (`shared/ui/native-select.tsx`) labelled "Language", after Theme and before Time zone; each option in its own name with its own `lang` attribute; order English, Español, Português (Brasil), Português (Portugal), 中文（简体）. product: five options do not fit a segmented control at 375; ux: the OS picker is the best touch target and keyboard control, zero JS; ia: language sits with display preferences, next to the zone that dates also use. | no search (five options do not need it) |
| 2 | (a) per string English, at runtime only; the type system makes a missing key in an existing translation a typecheck error, a test makes a missing translation file a failure, so the runtime fallback only covers literals not extracted yet and languages not shipped yet. | 3 | (b) `santi-language` in localStorage; `main.tsx` loads that language's chunk before the first render (English: nothing to load, no delay) and starts `/api/me` in parallel; when the account's language differs (changed on another device) the UI switches once and the mirror updates. No pre-paint script: the root is empty until React renders anyway. | a non-English first visit waits for one small cached chunk; a second device flips once |
| 4 | (b) the device's last language, not cleared on sign-out (unlike the theme, it reveals nothing); a new account still starts in English (owner rule): registering does not send the device language (open question 2 below). | a shared device keeps the previous person's language on the sign-in screen |
| 5 | (a) the language is the `Intl` locale for dates, numbers, relative times and plurals; the account zone (SAN-197) still decides the time. Architect (A):

- A1 Format: no dependency. Plain TS objects and a ~70-line `shared/i18n/i18n.ts`: `defineMessages(id,
  en)` with a `const` type parameter, `useT(namespace)` returning `t(key, params?)` and `t.rich(key,
  nodes)` (placeholders replaced by React nodes, for `<code>` and links inside a sentence), `{name}`
  interpolation, plurals as `{ one, other, ... }` objects picked with a cached `Intl.PluralRules(language)`
  and falling back to `other` (Spanish, French-style `many` for millions and Chinese `other`-only work with
  the same code), numbers in params through a cached `Intl.NumberFormat(language)`. Keys are typed
  (`keyof` the English object); params are a loose `Record<string, string | number>` (a wrong param name
  shows `{name}` in the rendered string, caught by the screen's test). A library (i18next, FormatJS)
  costs 10–40 KB and ICU parsing the product does not need.
- A2 Bundle split: **English stays co-located** with the code that shows it: each FSD slice with copy
  has `messages.ts` (`export const messages = defineMessages('features/account', { ... })`) in the
  same folder, so English costs nothing extra: the literal moves from the JSX into an object in the same
  chunk. **Each other language is one lazy chunk**: `app/i18n/<lang>.ts` is an eager `import.meta.glob`
  of every `messages.<lang>.ts`, loaded by dynamic import, so a Portuguese user downloads all Portuguese
  once (~10–12 KB gzip when every screen is done, cached as an immutable asset) and never waits per
  route. Rejected: one global English table (fails D39 on every route), per-route per-language chunks
  (a request waterfall on every navigation and a suspended screen on every switch), all languages
  inline per chunk (×5 copy per route). Translation files import only types (`import type { messages }
  from './messages'` then `satisfies Translation<typeof messages>`), so they pull no code into the chunk.
  The namespace id is the folder path; a test asserts it.
- A3 Migration `0033_user_language.sql`: `language text NOT NULL DEFAULT 'en' CHECK (language IN ('en',
  'es', 'pt-BR', 'pt-PT', 'zh-CN'))`, all five from the start (no migration per language); constant
  default, no rewrite on Postgres 17. Rust `Language` enum with per-variant `#[serde(rename)]` and
  `#[sqlx(rename)]` (BCP 47 tags, case-sensitive: `pt-br` is a 422), registered in `text_type!`.
- A4 Rollout: slices merge to `developer` and may ship before every screen is done, so each entry of
  `LANGUAGES` carries `released: boolean`; the control offers released languages, plus every language
  in dev builds (`import.meta.env.DEV`, true in vitest), and is not rendered while only English is
  offered. Releasing a language after native review is a one-line change. The server accepts all five
  from day one; an account set to an unreleased language through the API sees whatever is translated.
- A5 Raw-literal guard, zero deps: ESLint's built-in `no-restricted-syntax` on JSX text with letters and
  on string literals in `aria-label`, `placeholder`, `title`, `alt` and `label` attributes, enabled
  file by file in `eslint.config.js` as each batch extracts them (a ratchet). The last batch turns it
  on for all of `src/**/*.tsx` minus tests and the landing.
- A6 Errors: the web maps D24 `type` slugs to its own copy in `shared/api/messages.ts`; an unknown slug
  shows `detail` (English). Field errors keep the client-side checks the forms already run in the
  chosen language; a server field message that slips through stays English. Done in the auth batch.
- A7 Performance: `useT` reads the store through `useSyncExternalStore` and memoizes `t` per
  namespace and language; lookups are two map reads. Only components that call `useT` re-render on a
  switch, which is every component with copy. A switch is ordered by a counter so a slow chunk that
  arrives after a newer choice is dropped.

## States (ux)

Language control (native select, Preferences):

| State | Behavior |
|---|---|
| Hidden | Only English is offered (production until a language is released): no control, no empty row. |
| Idle | Shows the saved language in its own name. |
| Selected | The language chunk loads (no spinner: it is small and cached); when it arrives the whole UI, `<html lang>` and the mirror switch at once, focus stays on the select, then `PATCH /api/me { language }` goes out. Choosing again restarts with the latest value. |
| Saved | Status "Saved" (in the new language). |
| Failed | Loading or saving failed: UI, select and mirror go back to the last saved language; status "Could not save your language." |

- `role="status"` line under the select, linked by `aria-describedby`, like Theme.
- 375: full width, 44 px, 16 px text; 1440: same column as the other preferences. Each option carries
  `lang` so a screen reader pronounces it in its language.
- Every language: no clipped or overflowing text at 375 and 1440, light and dark. Portuguese and
  Spanish run ~30% longer than English: the Theme segments ("Claro / Escuro / Sistema") fit in three
  columns at 375.

## Acceptance

- A new account opens in English; `GET /api/me` answers `"language": "en"`.
- Switching in /account changes the UI at once, survives a reload, a new session and another device.
- A device whose last language was pt-BR shows pt-BR from the first render (no English flash) and the
  sign-in screen in pt-BR after sign-out.
- `PATCH /api/me` answers 422 on `language` for an unknown or wrongly cased tag; erasing an account
  resets it to `en`.
- Every screen of the SPA is translated in the four languages, dates, numbers, relative times and
  plurals follow the language; API errors are translated by `type`.
- A missing key in a translation fails `pnpm typecheck`; a missing translation file fails the suite;
  an extracted file with a raw literal fails `pnpm lint`.
- D39: English first visits grow by ≤ 2 KB on every route; each language chunk has a size-limit entry.
- Screenshots 375 and 1440, light and dark, in all five languages: nothing clipped.
- A language is released only after a native speaker's review.

## Owner questions

   or keep "issue".
2. Registering on a device whose last language is not English: the account starts in English (default,

   if a language should ship earlier.
