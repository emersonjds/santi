## Acceptance

Reports page (`/p/$key/reports`)
- Heading "Reports"; section "Velocity" above the sprint list.
- Velocity: bars for committed and completed per sprint, average line; SVG `aria-hidden`, followed by `<details>` "View as table" (caption "Velocity by sprint", columns Sprint, Committed, Completed, last row the average). Theme tokens only (no hex), light and dark.
- Sprint list rows: name, dates "{start} – {end}", goal (1 line, truncated, full text in `title`), committed, completed; the active sprint first with badge "In progress" and live completed points. A row opens its report.
- Empty (no sprint started): "No sprint has finished yet." + link "Go to Backlog". Active sprint only: the list shows it; the velocity box shows "No sprint has finished yet."
- Missing total: "—", never 0 (RP-26).
- Loading: skeleton rows and a skeleton of the chart's fixed height (CLS 0).
- Error: "Couldn't load reports." + Retry for the list; the chart has its own "Couldn't load velocity." + Retry.
- More than 50 sprints: "Show more" (keyset, D29).
- Archived project: the read-only banner shows; everything stays readable.
- 375px: card-list rows, 44px targets, no page scroll sideways; the chart box scrolls inside itself if needed.

Sprint report (`/p/$key/reports/$id`)
- Header: combobox picker (`shared/ui/command.tsx` + `popover.tsx`), "Previous sprint" and "Next sprint" buttons (`aria-label`), disabled at the ends; they keep focus, and a polite live region says "Now showing {sprint name}". Tab order: picker → previous → next → groups.
- Header shows name, dates "{start} – {end}", goal, "Committed {n}" and "Completed {n}" (RP-25, RP-34, RP-35).
- Active sprint: badge "In progress" + caption "Updates as the sprint moves."; groups use live status and points.
- Groups "Completed", "Not completed", "Removed from sprint", each with start and end totals; an empty group says "No issues".
- Rows: key, summary (1 line desktop, 2 at 375), type, priority, status pill, epic, points "{start} → {end}"; removed rows show "{start} → —" (OQ-9). Joined after start: badge "Added", screen-reader text "Added after the sprint started" (RP-28).
- Deleted work: a muted "Deleted issues" line in its group with its points.
- Over 50 rows in a group: first 50, then "Show all {n}"; past 200 rows `LongRows` virtualizes (D39).
- Loading: header and group skeletons. Error: "Couldn't load this report." + Retry; previous/next still work.
- 375px: stacked card rows, 44px targets.

CLI and MCP
- `santi sprints report SAN 12` prints the sprint line, committed/completed, then per group "{Group} — {n} issues, {start} → {end} points" and one line per row (`KEY summary (type, status) start → end`, `Added` suffix). `--json` prints `SprintReport`.
- MCP `get_sprint_report { project, sprint_id }`, read-only, returns `SprintReport`.
- Future sprint: 409 `sprint-not-started`; unknown id: 404; kanban: 409 `kanban-has-no-sprints`.

## Technical

Slice `crates/santi-server/src/reports/` (`domain.rs`, `repo.rs`, `service.rs`, `handler.rs`, `mod.rs`), merged in `lib.rs` next to `sprints::handler::router()`. DTOs in `crates/santi-types/src/reports.rs`.

| Endpoint | Response | Statements (D39 budget) |
|---|---|---|
| `GET /api/projects/{key}/reports/sprints?limit&cursor` | `Page<SprintTotals>` | 2: member, one page CTE |
| `GET /api/projects/{key}/reports/velocity` | `Velocity` | 2: member, the same CTE with limit 8 |
| `GET /api/projects/{key}/sprints/{id}/report` | `SprintReport` | 3: member, header with neighbors, rows |

DTOs:
- `SprintTotals { sprint: Sprint, committed: Option<f64>, completed: Option<f64> }`
- `Velocity { sprints: Vec<SprintTotals>, average_completed: Option<f64> }` (≤ 7 closed, oldest first)
- `SprintReport { sprint, newer_sprint_id, older_sprint_id, committed, completed, groups: Vec<ReportGroup> }`
- `ReportGroup { outcome: ReportOutcome, points_at_start, points_at_end, issues: Vec<ReportIssue>, deleted: Option<DeletedIssues> }`
- `ReportOutcome { Completed, NotCompleted, Removed }` (snake_case)
- `ReportIssue { key, summary, issue_type, priority, status_name, status_category, epic_key, epic_summary, points_at_start, points_at_end, added_after_start }`
- `DeletedIssues { points_at_start, points_at_end }`

Queries:
- History: CTE picks the page from `sprint` (`board_id`, `state <> 'future'`, keyset `(coalesce(closed_at, 'infinity'), id) < cursor's`, order the same descending, `limit + 1`), then aggregates its `sprint_issue` rows. Committed = `sum(points_at_start) FILTER (WHERE NOT added_after_start)`; completed = `sum(points_at_close) FILTER (WHERE outcome = 'completed')` when closed, else `sum(issue.points)` of rows with no outcome whose status is `done` (live). `coalesce(closed_at, 'infinity')` keeps the one active sprint first and the cursor uniform; `id` breaks ties (seeded sprints share a `closed_at`).
- Velocity: the history query, no cursor, limit 8; `domain::velocity` keeps the closed ones, takes 7, reverses, averages.
- Header: the board's started sprints with `lag`/`lead` over the same order, filtered to `id = $2`.
- Rows: `sprint_issue` for the sprint LEFT JOIN `issue`, `project`, `status`, parent (epic only), skipping subtasks (`issue_type IS DISTINCT FROM 'subtask'`), ordered by number. `domain::group_rows` decides each row's group (stored outcome; none → live done/not done; deleted with none → removed), its end points (removed → none; closed → `points_at_close`; active → current points) and the RP-26 totals.

Indexes: none new. Rows use `sprint_issue_sprint_issue_key (sprint_id, issue_id)` and primary keys; history and header read a board's sprints through `sprint_board_idx (board_id, id)` (tens to hundreds of rows) and aggregate only the page. Ceiling: thousands of sprints per board; upgrade: index on `(board_id, coalesce(closed_at, 'infinity') DESC, id DESC)`. Confirm with `EXPLAIN ANALYZE` on the seed (20 sprints, 5k issues), p95 < 50 ms.

Migration `0019_imported_sprint_facts.sql`: one idempotent `INSERT … SELECT … ON CONFLICT DO NOTHING` writing completed facts (`added_after_start` false, start = close = current points) for issues sitting in a closed sprint. Native closed sprints already have those rows, so it only fills imported ones. `imports::repo` writes the same facts when it inserts a closed sprint's issues.
