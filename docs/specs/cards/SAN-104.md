# SAN-104 — Archived project is read-only in place

Owner: an archived project still shows controls that fail with 409 when used. Baseline: SAN-70 Q3 (archived = read-only, banner, controls `aria-disabled` in place), `behavior/organizations.md` OR-47.

## Questions

| # | Question | product | ux | ia | Winner (architect) |
|---|---|---|---|---|---|
| 1 | Hide or disable | read-only for all | `aria-disabled` in place (SAN-70 Q3) | — | **Disable in place** every action a person would look for: Create issue, Create sprint, Start/Complete sprint, Delete, More, Import issues, field editors, comment box. They stay focusable with `aria-describedby="archived-note"`. **Hide** only affordances that mean nothing without writes: drag handles, empty drop slots, the import upload step (replaced by the note). |
| 2 | One lock | — | — | — | Shared `Button`, `Input`, `Textarea`, `NativeSelect` lock themselves inside `<WriteLock>`; the project route loads the project before rendering, so the lock never starts open. |
| 3 | Menus | — | Radix items `disabled` | — | Radix menu items use `disabled` (keyboard skips them); the trigger stays enabled so the read items (Copy link, Open as page) still work. |
| 4 | Copy | — | — | — | Banner: the existing archived banner. Import page: "Unarchive the project to import issues." Empty sprint/backlog section on an archived project: "No issues." |

## Acceptance

- Every write control on board, backlog, issue page, issue dialog, sprint header, board settings and import is inert on an archived project: click, Enter, Space, keyboard drag and pointer drag do nothing and send no request.
- Locked buttons keep their own `aria-describedby` and add `archived-note`; locked fields are `readOnly` and look read-only (no hover border).
- A direct link to an archived board renders the plain layer from the first paint (no DnD layer swap).
- Unarchived projects: no change in any shared control (`disabled`, `type=submit`, `asChild`).
- States: archived banner `role="status"`, phone 375px (44px targets kept), dark theme, keyboard focus reaches locked buttons and reads the note.

## Deviations

- First build hid Create issue and the issue-page Delete/More; `qa` flagged it against SAN-70 Q3. Resolved by Q1 above: disabled in place.
