# SAN-135 — Rich text description and comments with @mentions

Baseline: `behavior/editor-and-comments.md` ED-1..ED-50 (documented; live observation of the edit
flow and toolbar was not possible this round, see OQ-3/4/5 there). SAN-136 owns the comment thread
layout (composer collapse, M shortcut, quick replies, per-comment actions); this card owns the
editor, the stored format, rendering and mentions, used by the description and the comment composer.

Owner (card, 2026-10-17): description and comments read as one dense block; wants a toolbar (text
style, bold/italic, lists, code, link, emoji, undo/redo), readable rendering, and @mention of project
members while typing, shown as chips.

Facts today: `issue.description` is plain `text` capped by `MAX_DESCRIPTION`
(`crates/santi-server/src/issues/domain.rs`), comment bodies are plain text, the web renders both as
plain text, and no editor or Markdown dependency is installed. D39: ≤ 170 KB gzip initial JS per
route.

Panel: `product`, `ux`, `ia` voted, `architect` challenged. Cross-cutting part: D50.

Facts the architect added:
- Description cap 65,536 chars (`MAX_DESCRIPTION`, CHECK in migration 0013); comment cap 20,000
  (`check_comment_body`, CHECK in migration 0006, importer `take(20_000)`, web `maxLength`).
- Measured initial JS today (`pnpm size`, `developer` build): issue page 146.1 KB, backlog 151.4 KB,
  board settings 153.7 KB. The issue dialog on board and backlog is already lazy (`issue-overlay.tsx`).
- Bundle sizes, gzip, whole package with its deps (bundlephobia): `@codemirror/view` (+ state) 77.6,
  `@codemirror/language` 86.7, `@codemirror/commands` 89.6, `@codemirror/autocomplete` 89.1 (all
  three include view/state), `@lezer/markdown` 21.8, `@codemirror/lang-markdown` 170.6 (pulls
  `lang-html`, CSS and JS languages); `@tiptap/starter-kit` 103.9 before React and Markdown glue;
  `lexical` core 61.5 before React, lists, links, Markdown; `react-markdown` 33.3 + `remark-gfm` 9.6;
  `marked` 13.5 + `dompurify` 11.2; `micromark` + GFM 21.8; `markdown-it` 39.8.
- `react-markdown` (context7): raw HTML is kept as text by default, `defaultUrlTransform` allows only
  http, https, irc, ircs, mailto, xmpp and relative URLs, `components` maps tags to React components.
- CSP (`lib.rs`) has `style-src 'self' 'unsafe-inline'` (CodeMirror injects its styles: allowed) and
  `img-src 'self' data:` (images by external URL are blocked).
- `shortcuts.ts` already ignores keys from `isContentEditable` targets (ED-6 holds for a
  contenteditable editor). Members (`MemberInfo`: `user_id`, `email`, `display_name`) are already
  loaded by the project route (`membersQuery`); the MCP has no members tool, the CLI no members command.

## States (ux)

- Read, empty: description "No description yet." + "Edit description"; no comments → the composer only.
- Read, filled: Markdown rendered; mention chips with current name (avatar initial, brand token);
  links underlined; code blocks scroll sideways; the whole detail keeps `DetailSkeleton` until both the
  issue and the renderer chunk are ready (CLS 0).
- Editor empty: placeholder "Add a description…" / "Add a comment…", toolbar visible and enabled, no counter.
- Focused, no selection: caret visible; toolbar `aria-pressed` only for marks at the caret.
- Text selected: toolbar shows the marks the selection carries; a button toggles that mark.
- Dirty: Save enabled, Cancel always enabled; Esc discards (same as Cancel today).
- Saving: Save shows busy and is disabled (no double submit); editor read-only until the request ends.
- Error: inline message under the field (`fieldMessage`), draft kept, focus stays in the editor.
- Editor chunk not loaded yet (slow network): the field is today's `Textarea`, typing works; focus
  swaps to the editor with the same text and caret once it loads; a failed chunk keeps the textarea
  (stale-chunk reload rules apply).
- Near the cap: "N characters left" under the field from 90%; at the cap input stops and an oversize
  paste shows the inline message.
- Mention picker: list under the caret, up to 8 rows; no match → one muted "No matching members" row,
  picker stays open; Esc closes it without inserting.
- Mention of someone no longer a member: captured name as muted plain text, no avatar, not a link.
- Read-only (archived project, SAN-104 `WriteLock`): rendered text only, no edit trigger, no composer.
- 375px: toolbar scrolls inside itself, 44 px targets, editor text 16 px (`text-base`), picker width
  ≤ viewport minus 16 px gutters, no page horizontal scroll; code blocks scroll inside themselves.
- Dark: toolbar, picker, chips, code background and links on D36 semantic tokens (no raw hex); chip
  and link contrast as D36 brand-300/400.
- Keyboard: Tab reaches toolbar then editor then Save/Cancel; inside a list Tab indents; Esc closes
  picker, then cancels; page shortcuts never fire inside the editor (ED-6).
