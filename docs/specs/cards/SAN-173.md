# SAN-173 — Team progress, slice 1: who is doing what, and how far along

Owner 2026-10-19: the lead needs to see what each person is doing and how it is going, to hand out cards this week. Slice 1 covers the view across people for the running work; sprint-planning workload (points per person in a future sprint) is slice 2.

## Context

- The board already filters by person: `AssigneeToggles` (`web/src/widgets/board/filter-controls.tsx:36`) renders an avatar per project member and writes `search.assignee` (ids) in the URL; the server applies `IssueFilter.assignee` (`crates/santi-types/src/issues.rs:280`, `boards/domain.rs:201`). "Only my issues" sits next to it. There is no "Unassigned" toggle, and the backlog has no person filter.
- No aggregate by person exists. The sprint report (`reports/repo.rs:117`, one query, grouped in Rust) is the model for a new aggregate endpoint.
- No "time in status" exists; `issue.updated_at` is the only age signal.
- Perf budgets: board 4 statements, backlog 5, sprint report 3 (`tests/perf_budget.rs`).

## Scope

Server:
- `GET /api/projects/{key}/people` → for the active sprint (Scrum) or the whole board (Kanban, done window applied like the board): one row per assignee plus one for unassigned, each with issue count and points per status category (to do, in progress, done) and `stuck` = in progress with no update for N days. One SQL query grouped by assignee and category; budget 1–2 statements in `perf_budget.rs`. Scrum with no active sprint → `{ sprint: null, people: [] }`.
- `IssueFilter` gains an "unassigned" value for `assignee` (decide the wire format with the architect; the board and backlog both honour it).

Web:
- "Unassigned" toggle after the member avatars on the board; the same person filter on the backlog filter bar.
- The per-person summary (placement decided by the panel).

CLI / MCP:
- `santi report people <KEY>` (text table + `--json`); MCP tool `get_team_progress { project }` (read-only).

Out of this slice: future-sprint workload (slice 2, takes the workload part of SAN-78), per-status entry timestamps, notifications about stuck work.

## Decisions

Panel 2026-10-21: product, ia and ux unanimous on all five; tab position split (ia 2nd, ux 4th), ux wins: Board and Backlog stay adjacent for the daily loop. Architect challenge (orchestrator):
- Unassigned travels as `unassigned=true` on `IssueFilter` (same style as `recently_updated`), OR-combined with `assignee` ids; `assignee` keeps its `Vec<i64>` contract.
- `GET /api/projects/{key}/people` is one SQL query grouped by assignee and status category; `stuck` is counted in the same query (`in_progress` and `updated_at < now() - 3 days`). Budget pinned in `perf_budget.rs`.
- The expanded row loads that person's issues from the existing board endpoint (`/board?assignee={id}` or `?unassigned=true`, same scope as the summary), no new list endpoint; flattened client-side, columns in board order.

## Acceptance

- `GET /api/projects/{key}/people` on a Scrum project with an active sprint returns one row per assignee in the sprint plus Unassigned, each with issues and points per category and `stuck`; with no active sprint, `sprint: null` and no rows; on Kanban, the board scope with the done window. Non-members get 404. Statement budget pinned.
- `unassigned=true` filters the board and backlog to issues with no assignee, alone or together with `assignee` ids.
- The People tab renders every state above at 1440 and 375, light and dark; row order as specified; expanding a row lists that person's issues; "Show on board" opens the filtered board.
- The board and backlog filter bars show the Unassigned avatar after the members.
- `santi report people <KEY>` prints one line per person (name, done/total issues and points, stuck) and `--json`; MCP `get_team_progress { project }` returns the endpoint's JSON.
- Gates: server (fmt, clippy, tests, sqlx check, coverage), web (typecheck, lint, format, coverage > 90 %, size budget for the new route), qa review (contract), ux screenshot review.

## States (ux)

- **Header**: Scrum → sprint name + date range ("Sprint 14 · Oct 20 – Oct 24"); Kanban → "Kanban board". No toolbar.
- **Row anatomy** (1440, left to right): avatar → name → stuck badge (if any) → "3/8 issues · 5/13 pts" → stacked bar (to do / in progress / done, same `status-todo` / `status-progress` / `status-done` tokens as the status pill) on the row's right half.
- **Stuck badge**: text "Stuck ×N"; title/tooltip "No update in 3 or more days". In the expanded list, stuck issues each show "5 days since update"; others show nothing.
- **Expanded row** (click or Enter/Space on the row button): issue list — key, summary (truncate, no wrap), status pill, days-since-update (stuck issues only); footer link "Show on board" → `/p/{key}/board?assignee={id}` (`?unassigned=true` for Unassigned).
- **Sort**: stuck count desc, then in-progress count desc, then name asc; "Unassigned" always last regardless of its counts.
- **Loading**: 5 skeleton rows at the final row height (avatar circle, two text bars, bar placeholder).
- **Error**: "People did not load." + "Try again" button; retry refetches, focus stays on the button.
- **No active sprint (Scrum)**: "No sprint is running." + "Go to Backlog" link to start one.
- **Empty sprint/board**: Scrum with 0 issues: "This sprint has no issues yet."; Kanban: "The board has no issues yet." No rows.
- **One person**: same row layout, no banner.
- **Many people**: plain scrolling list under a sticky header; no pagination (member counts are small).
- **Long text**: names truncate with an ellipsis; full name on focus/hover title.
- **No permission**: tab hidden for users without project access, same rule as Board.
- **375 px**: full-width rows, 44 px minimum height; avatar + name on one line, bar directly under it full width, counts under the bar, stuck badge inline after the name; the whole row is the tap target; "Show on board" is its own 44 px link inside the expanded block.
- **Dark theme**: bar segments and pill tones follow the existing status-category tokens; no separate palette.
- **Keyboard**: each row is a `<button aria-expanded>`; Tab visits rows in sort order; Enter/Space toggles; the expanded issue items and "Show on board" join the tab order right after their row; collapsing returns focus to the row button.
- **Screen reader**: the bar is `aria-hidden`; a visually-hidden string carries what the bar shows and the visible numbers don't: "2 to do, 3 in progress, 3 done".
- **Unassigned avatar toggle** (board and backlog filter bar): dashed-circle avatar, no initials, `aria-label="Unassigned issues"`; same `role="button" aria-pressed` and focus ring as member avatars; combines with member picks (OR filter); 36 px desktop / 44 px phone target, placed after the last member avatar.
