# SAN-173 — Team progress, slice 1: who is doing what, and how far along

Owner 2026-10-19: the lead needs to see what each person is doing and how it is going, to hand out cards this week. Slice 1 covers the view across people for the running work; sprint-planning workload (points per person in a future sprint) is slice 2.

## Context

- The board already filters by person: `AssigneeToggles` (`web/src/widgets/board/filter-controls.tsx:36`) renders an avatar per project member and writes `search.assignee` (ids) in the URL; the server applies `IssueFilter.assignee` (`crates/santi-types/src/issues.rs:280`, `boards/domain.rs:201`). "Only my issues" sits next to it. There is no "Unassigned" toggle, and the backlog has no person filter.
- No aggregate by person exists. The sprint report (`reports/repo.rs:117`, one query, grouped in Rust) is the model for a new aggregate endpoint.
- No "time in status" exists; `issue.updated_at` is the only age signal.
- Perf budgets: board 4 statements, backlog 5, sprint report 3 (`tests/perf_budget.rs`).

## Scope

Server:
- `GET /api/projects/{key}/people` → for the active sprint (Scrum) or the whole board (Kanban, done window applied like the board): one row per assignee plus one for unassigned, each with issue count and points per status category (to do, in progress, done) and `stuck` = in progress with no update for N days. One SQL query grouped by assignee and category; budget 1–2 statements in `perf_budget.rs`. Scrum with no active sprint → `{ sprint: null, people: [] }`.
- `IssueFilter` gains an "unassigned" value for `assignee` (decide the wire format with the architect; the board and backlog both honour it).

Web:
- "Unassigned" toggle after the member avatars on the board; the same person filter on the backlog filter bar.
- The per-person summary (placement decided by the panel).

CLI / MCP:
- `santi report people <KEY>` (text table + `--json`); MCP tool `get_team_progress { project }` (read-only).

Out of this slice: future-sprint workload (slice 2, takes the workload part of SAN-78), per-status entry timestamps, notifications about stuck work.

## Decisions

Panel 2026-10-21: product, ux, ia vote; architect challenges on data and performance. Winner column filled after the vote.

| # | Question | Options | Winner |

| 1 | Where the per-person summary lives | (a) a new project tab "People" next to Board / Backlog / Reports; (b) a section on the Reports page above the sprint list; (c) a collapsible panel above the board, under the filter bar | |
| 2 | What a person row shows | (a) avatar, name, issues and points as "done / total", one stacked bar (to do / in progress / done), stuck count; (b) three columns with counts per category plus points, no bar; (c) (a) plus the titles of their in-progress issues inline | |

| 5 | Unassigned on the board | (a) a dashed-circle avatar labelled "Unassigned" at the end of the avatar row, combinable with people; (b) a separate toggle like "Only my issues" | |
