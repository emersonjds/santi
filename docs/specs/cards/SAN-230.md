# SAN-230 — Welcome tour on first sign-in, replayable any time

Owner, 2026-11-17: someone signing in for the first time needs to understand quickly how to use
santi. A short tour appears on first access and can be opened again later.

## Context

- App shell: `web/src/widgets/app-shell/` (top bar with search, Create button, notifications,
  account menu with "Keyboard shortcuts" → `shortcut-sheet.tsx`; `?` opens it via `shortcuts.tsx`;
  sidebar with Home, projects, Recent, Starred). Pages: home, projects, board, backlog, issue,
  reports, people, settings, import, account.
- Preferences live on the account (D54: theme and time zone in `User` / `PATCH /api/me`, server is
  the source, `localStorage` only as a cache against flashes).
- Budgets D39: every route under its `.size-limit.js` limit (~3 KB headroom after SAN-204 pass 2);
  the tour must load only when it opens (lazy chunk with its own size entry).
- No i18n yet (SAN-199): copy in English, written so it can move into the dictionary later.
- A new account starts with no projects; the home page has an empty state.

## Open questions (panel)

| # | Question | Options |
|---|---|---|
| 1 | Form | (a) a short dialog carousel (4–6 steps, text + a small illustration made of existing UI pieces, no images); (b) coach marks pointing at real UI elements (spotlight on Create, sidebar, search…); (c) a checklist card on the home page ("Create a project", "Add an issue", "Invite your team", "Connect an AI assistant") that ticks itself as things happen |
| 2 | Steps and order | which 4–6 steps (projects and board, backlog and sprints, create with `c`, issue detail, invite the team, search ⌘K, AI/MCP and CLI) |
| 3 | When it shows | (a) first sign-in only, once; (b) first sign-in and until dismissed; (c) after creating the first project |
| 4 | Where to replay | (a) account menu item "Take the tour"; (b) also a line in the shortcuts sheet (`?`); (c) also in /account Preferences |
| 5 | "Seen" state | (a) `tour_seen_at` on the account (server, like theme); (b) localStorage only |
| 6 | Phone (375) | how the chosen form behaves on a phone (full-screen sheet, bottom sheet, or no coach marks on phone) |

Architect challenge: no tour library (bundle), coach marks must survive layout changes and the
collapsed sidebar, keyboard and screen reader first (focus trap, Esc closes, focus returns), a new
column needs a migration and an API field (contract change → qa).

## Decisions

Panel 2026-11-18 (one agent, product/ux/ia lenses). Architect (orchestrator) adjustments marked A.

| # | Winner | Trade-off |
|---|---|---|
| 1 | (a) short dialog carousel (votes: product c, ux a, ia a) | teaches less "by doing"; home empty state gets one "Take the tour" link instead of a tracked checklist |
| 2 | 5 steps in sidebar order, each naming a real shortcut (all exist in shortcut-sheet.tsx) | AI/MCP and CLI share the closing step |
| 3 | (a) first sign-in only, once (unanimous) | someone who skips fast relies on the replay entries |
| 4 | (a) account menu "Take the tour" + (b) a row in the shortcuts sheet (unanimous) | no entry in /account |
| 5 | (a) server-side `tour_seen_at` (unanimous) | migration + API field → qa |
| 6 | Same content full-screen on phones | — |

A1: one `Dialog` only, made full-screen below `sm` with classes (`max-sm:h-dvh max-sm:max-w-none max-sm:rounded-none`); no separate Sheet component.
A2: marking seen is fire-and-forget; if the write fails the tour may show again on the next sign-in. No retry or toast logic.
A3: step 4 copy fixed to where inviting really lives (the project's Invite button).
A5: the migration marks every existing account as seen (`tour_seen_at = now()`), so only accounts created after the release get the automatic tour; everyone can replay it.
A4: the tour chunk is lazy, loaded only when it opens, with its own `.size-limit.js` entry.

## Copy (exact)

1. "Welcome to santi" — "Press C anywhere to create an issue. This short tour covers the basics in under a minute."
2. "Board and backlog" — "Work moves on the board; plan it in the backlog. Jump with G then B, or G then L."
3. "Search and jump" — "Press / to search inside a project, or ⌘ K to jump to any project."
4. "Invite your team" — "Projects are more useful together. Use Invite at the top of a project to add teammates with a link."
5. "Shortcuts, CLI and MCP" — "Press ? any time for the full shortcut list. The CLI and an AI assistant can read and change issues too."

Buttons: "Back" (hidden on step 1), "Next" (1–4), "Done" (step 5), "Skip tour" (every step). Counter "Step {n} of 5" (aria-live polite). Replay: account menu item "Take the tour"; shortcuts sheet row "Replay the welcome tour" (a button row, no key); home empty state (`features/project/no-projects.tsx`) link "Take the tour". Shortcut keys rendered with the `kbd` markup used in shortcut-sheet.tsx.

## States (ux)

- 1440: centered Dialog (shared/ui/dialog.tsx, pattern of ShortcutSheet), max-w ~28rem; per step a lucide icon + the kbd chips, title, body, counter, button row; buttons h-11.
- 375: same Dialog full-screen (A1), buttons pinned at the bottom, text and kbd chips wrap, no horizontal scroll.
- Opens automatically once when `me.tour_seen_at` is null (after the shell mounts, not on /login, /join or legal pages). Esc, Skip, Done, or any route change closes it and marks seen (`PATCH /api/me { "tour_seen": true }`). Replays never write.
- Focus: Radix trap; Tab Back → Next/Done → Skip; on close focus returns to the opener (menu trigger on replay; on auto-open, the main content). Reduced motion: no transition between steps.
- Invited member with projects: same tour.

## Acceptance

- Data: `app_user.tour_seen_at timestamptz NULL`; `User.tour_seen_at: string | null`; `PATCH /api/me` accepts `tour_seen: true` (server stamps now(), idempotent; `false` not accepted); included in the account export like theme.
- New account: the tour opens once after the first sign-in; skip and finish both mark it seen on the
  account (persists across devices); replay works from the chosen entry points.
- Keyboard: Tab order, Esc closes, focus returns; screen reader announces step n of N.
- Lazy chunk with a size entry; every route still within its limit.
- e2e: first sign-in shows the tour, skip, replay from the menu.
