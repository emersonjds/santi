# SAN-146 — CLI and MCP create projects

Owner (2026-10-18): the CLI and the MCP server create projects. Needed by SAN-145 (import every
project from the old tracker). No new mechanic: the web "New project" form and `POST /api/projects`
already define the rules; this card only exposes them, following the cli-mcp rule "every manual
action has a subcommand and an MCP tool with the same name and arguments".

## Decisions (from existing patterns, no open questions)

| # | Question | Winner | Pattern followed |
|---|---|---|---|
| 1 | Command shape | `santi projects create <KEY> --name <NAME> [--type scrum\|kanban]` | positional project key like `projects archive <KEY>`; `--name` like `sprints create --name` |
| 2 | Default type | `scrum` | web form default and the most common team setup |
| 3 | MCP tool | `create_project { key, name, board_type? }` | tool names mirror commands (`create_sprint`, `create_issue`) |
| 4 | Output | the project line `projects list` prints; `--json` prints the API body | every create command prints the created row |
| 5 | Errors | API problem surfaces verbatim (bad key 422, duplicate key 409), exit codes as README | `error.rs` mapping |

## Acceptance

- `santi projects create WEB --name "Web app"` creates a scrum project and prints it; `--type kanban` creates a kanban one.
- Duplicate key exits 5 with the server's message; a malformed key is rejected before the request (ProjectKey parse), exit 2.
- MCP `create_project` creates it and is listed in the tools list; errors come back as tool errors.
- README command list and `docs/mcp.md` tool list mention it.
