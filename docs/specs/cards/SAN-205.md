# SAN-205 — Scheduled logical backups for self-hosters

Architect, 2026-11-18. No UI; operators only.

## Decisions

- Off unless `SANTI_BACKUP_HOUR_UTC` (0–23) is set. `SANTI_BACKUP_KEEP` (default 14, at least 1) is
  how many runs are kept. An empty value counts as unset; an invalid one stops startup naming the
  variable.
- Destination: the attachments storage (D53, bucket or local disk), under
  `backups/{YYYY-MM-DDTHHMMSSZ}/{KEY}.json.gz`: one gzip-compressed project export per project, the
  body `POST /api/projects/restore` reads (the `projects[]` entry of `GET /api/me/export`), then
  `backups/{run}/manifest.json` last (keys, issue and comment counts, santi version).
  `santi restore` also accepts such a single-project file, gzip-compressed or not. Only path
  segments named like a run are runs; anything else under `backups/` is never touched.
- Each file is checked before it is written: the restore's own validation (`restore::domain::check`)
  and the 50 MB body limit; a refused project is logged as an error and skipped, the others are
  written. Comments and parent keys naming issues the export lacks (concurrent writes) are dropped;
  comments are read after the issues.
- Scope: every live and archived project of the instance, trashed ones excluded, regardless of
  user. The export is read through one of the project's members, admins first; a project with no
  member is skipped with a warning. Attachments are not copied.
- Schedule: a background task checks every 5 minutes. A run is due once the day's
  `HOUR_UTC:00` has passed and no run named at or after it exists in storage, so restarts and late
  starts do not double-run and a missed hour still runs that day. One replica runs it, holding the
  session advisory lock `pg_try_advisory_lock(LOCK_KEY)` for the run; the others skip.
- A failed run deletes the files it wrote, is logged at error level (Sentry when configured) and is
  retried an hour later. A crash mid-run leaves a run without a manifest: it still counts for "due"
  (no crash loop), and the next written run removes it, logging `backup run … was incomplete;
  removed`.
- Retention: after a run that wrote at least one project, every finished run (with a manifest) but
  the newest `KEEP` is deleted; a run that wrote nothing deletes nothing.
- Logging: one info line per run with the run name, project count and duration.
- `pg_dump` stays the full-fidelity option (docs give a sidecar snippet).

## Acceptance

- Two projects → a run writes two `.json.gz` that decompress to bodies the restore endpoint accepts.
- A second check in the same day writes nothing; a check before the hour writes nothing.
- With `KEEP = 2`, three daily runs leave the newest two.
- While another session holds the lock, a check writes nothing.
