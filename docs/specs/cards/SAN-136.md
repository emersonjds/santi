# SAN-136 — Comment thread UI: spacing, composer and per-comment actions

Baseline: `behavior/editor-and-comments.md` ED-29..ED-45 (comment area, quick replies, edit,
delete, rights, reactions, replies, views, ordering, permalink) and OQ-9..OQ-15 there. The editor,
format and mentions shipped in SAN-135 (D50). Owner (card, 2026-10-17): santi comments are cramped;
wants a collapsed composer "Add a comment…" with quick-reply chips and a keyboard hint, an expanded
composer with toolbar and Save/Cancel, each comment with avatar, name, relative time, a body with
comfortable spacing, and actions. Clean room: never copy quick-reply texts.

Facts today: `web/src/widgets/issue-detail/issue-comments.tsx` lists comments oldest first with
avatar, name, relative time and the Markdown body, and a composer that becomes the SAN-135 editor;
the API has list and create only (no edit, delete, reactions, replies). SAN-76 owns comment edit in
its scope list; SAN-94 owns the Activity tabs (All, Comments, History, Work log).
Found by the architect: the web reads one page of 200 comments (`commentsQuery`, `PAGE = 200`) and
never shows comment 201 on; the delete rule "admin or the person who wrote it" already exists twice
(`issues::domain::check_delete`, web `entities/issue/may-delete.ts`).

## Needs the owner

Baseline rules this card does not ship and no sprint card owns; each is a proposed card:

- **Comment reactions (ED-40, OQ-14):** thumbs up under each comment, add-reaction with a short set
  and the full picker; who reacted on hover; toggle off. Table `comment_reaction (comment_id,
  user_id, emoji)` with `ON DELETE CASCADE`; web, CLI and MCP.
- **Comment replies and threaded view (ED-41, ED-42, ED-43, OQ-9, OQ-12):** nested replies inheriting
  the parent's visibility, collapse of a long thread, the threaded Comments view (after SAN-94's
  tabs). Needs the delete-with-replies rule (OQ-12): a tombstone instead of D52's hard delete.
- **Restricted comments (ED-38):** visible to a group or project role only. santi has two roles and
  no groups, so it needs a rights decision first.
- **AI-drafted quick replies (ED-30, AI tier):** santi has no AI provider; a separate feature.
- **Watch on comment and silent update (ED-32, ED-39):** both need watchers and notifications
  (SAN-54); santi sends no notifications yet.

## Contract (D52)

- `PATCH /api/projects/{key}/issues/{number}/comments/{id}`, body `UpdateComment { body }`
  (`deny_unknown_fields`, same `check_comment_body`) → 200 `Comment`.
- `DELETE /api/projects/{key}/issues/{number}/comments/{id}` → 204.
- `Comment` gains `edited_at: Option<DateTime<Utc>>`, `edited_by_id: Option<i64>`,
  `edited_by_name: Option<String>` (all null until the first real edit; `#[serde(default)]` so a
  new CLI reads an old server).
- Rights: the author or a project admin, for both (`check_delete(member.role, member.user_id,
  comment.author_id)`); an erased author's comment is admin-only.
- Status order: not a member or unknown project 404 (extractor) → archived 409 `project-archived`
  (extractor) → issue not in the project 404 → comment not on that issue 404 (also another
  project's id) → neither author nor admin 403 → bad body 422.
- Edit with the same body (after `check_comment_body`) returns the comment untouched: the marker
  means the text changed (OQ-13). Earlier bodies are not kept (SAN-76's history may log them).
- Both writes touch `issue.updated_at`; edit also records the caller's `worked_at`
  (`issue_activity`, the same CTE as `insert_comment`). Delete is hard; no tombstone.
- Migration `0022_comment_edit.sql`: `ALTER TABLE issue_comment ADD COLUMN edited_at timestamptz,
  ADD COLUMN edited_by bigint REFERENCES app_user (id), ADD CONSTRAINT issue_comment_edited_check
  CHECK ((edited_at IS NULL) = (edited_by IS NULL))`. Additive, no backfill; `app_user` rows are
  never deleted (D45), so the FK holds.
- CLI: `santi issues comment-edit <ISSUE> <ID> <BODY>`, `santi issues comment-delete <ISSUE> <ID>
  [--yes]` (asks "Delete comment <ID> on <ISSUE>?" like `issues delete`); `santi issues comments`
  text starts each entry with `#<id>` and ends the header line with `· edited` when edited.
- MCP: `edit_comment { issue, comment_id, body }` (not destructive), `delete_comment { issue,
  comment_id }` (`destructive_hint = true`, "cannot be undone"); `list_comments` already returns
  ids.

## States (ux)

- **Empty thread:** no list; "No comments yet." (`text-sm text-subtle-foreground`) above the
  composer.
- **Collapsed composer:** a full-width button styled as the textarea, `h-11 md:h-9`, text
  "Add a comment…", `M` in a `<kbd>` pill on the right from `md` up, `aria-keyshortcuts='m'`;
  quick-reply chip row under it.
- **Quick replies:** `role='group' aria-label='Quick replies'`, one row, `overflow-x-auto`, chips
  `h-8 rounded-full border px-3 text-sm whitespace-nowrap` with 44px hit area at 375. A chip fills
  the draft, expands the composer and puts the caret at the end; it never posts. The row hides once
  the draft has text and while editing a comment. Absent when built with `VITE_QUICK_REPLIES=off`.
- **Expanded composer:** `RichTextField` with toolbar, `autoFocus`; footer Save (primary) +
  Cancel (ghost). Cancel or Escape collapses, keeps nothing, focus back on the collapsed trigger.
  Mod-Enter saves.
- **Posting:** optimistic as today (the comment shows under the viewer's name at once); composer
  collapses, focus back on the trigger.
- **Failed post:** the comment leaves the list, the composer re-expands with the draft restored and
  focus in the editor, toast "Couldn't add the comment" (existing).
- **Comment:** `<li id='comment-{id}'>`, avatar `size-8`, line one name (`font-medium`) + time
  (`text-xs text-subtle-foreground`, relative < 7 days then date, `title` = full date and time)
  + `(edited)` when edited; body `MarkdownView`, `leading-relaxed`.
- **More menu:** `Ellipsis` ghost trigger `size-11 md:size-8`, `aria-label='Comment actions'`,
  shown on hover and focus-within of the comment from `md` up, always visible at 375. Items:
  Copy link (everyone), Edit and Delete (author or admin; Delete `variant='destructive'`).
- **Copy link:** writes the full-page URL `…/p/{key}/issues/{n}#comment-{id}`, toast "Link copied".
- **Arrival by permalink:** the issue opens, the target scrolls into view (`block: 'center'`), gets
  `bg-muted` for 3 s, no animation under `prefers-reduced-motion`. A missing id (deleted) opens the
  issue with no message.
- **Editing a comment:** the body swaps for `RichTextField` prefilled, `autoFocus`, caret at end,
  Save/Cancel; menu trigger hidden. Save waits for the server (D50 amendment): Save busy, editor
  read-only, draft kept with the message on error. Unchanged text closes without a request.
  Cancel/Escape restores the view; focus back on the menu trigger.
- **Edited marker:** `(edited)` after the time, `title='Edited by {name} · {date and time}'`, name
  from the members list by `edited_by_id`, else `edited_by_name`.
- **Delete confirm:** `AlertDialog`, title "Delete this comment?", body "It can't be undone.",
  Cancel + destructive Delete (44px). Confirm removes the comment at once; on error it comes back
  with toast "Couldn't delete the comment". Escape/Cancel returns focus to the menu trigger.
- **Long thread:** every page loaded, plain scroll.
- **Archived project:** `WriteLock` as today: composer, chips, Edit and Delete hidden; Copy link
  stays.
- **375px:** composer, chips and comments full width, chips scroll inside their row, no sideways
  page scroll, every control ≥ 44px, editor fonts ≥ 16px.
- **Dark:** existing tokens only (`--muted`, `--muted-foreground`, `--border`,
  `--subtle-foreground`, `--destructive`).

## Acceptance

- Backend (`crates/santi-server/tests/comments_search.rs`): author edits → 200 with `edited_at`,
  `edited_by_id`, `edited_by_name`; same body → no marker; admin edits and deletes another member's
  comment; plain member on someone else's → 403; comment id of another issue or project → 404;
  outsider → 404; archived → 409; empty and over-cap body → 422; delete → 204 then gone from the
  list; both bump `issue.updated_at`; OpenAPI lists both routes and the new fields. Domain unit test
  for the unchanged-body rule. `scripts/sqlx-prepare.sh --check` clean; coverage ≥ 90%.
- Web unit (`issue-detail.test.tsx`): collapsed trigger; M expands and focuses; chip fills, never
  posts, row hides with text; Save posts, Cancel/Escape collapse with focus back; failed post
  restores the draft; menu shows Edit/Delete for author and admin only, Copy link for all; edit
  saves, unchanged text sends nothing, error keeps the draft; delete confirm, optimistic remove and
  rollback; `(edited)` with its title; time rule (< 7 days relative, then date, title absolute);
  `VITE_QUICK_REPLIES=off` hides chips; archived hides writes; 201 comments all render; permalink
  scroll + highlight. Coverage > 90% on 4 metrics.
- CLI/MCP (`crates/santi-cli`): parse tests for `comment-edit` and `comment-delete` (with and
  without `--yes`); client paths `…/comments/{id}` with PATCH and DELETE; `comments_text` shows
  `#id` and `· edited`; MCP tools listed with their annotations and call the client.
- e2e (`web/e2e/issues.spec.ts`): post, edit, reload shows `(edited)`, delete with confirm, reload
  shows it gone; copy link opens the issue at that comment (one test each, no more).
- Screenshots 1440 and 375, light and dark: empty, collapsed with chips, expanded, a thread with an
  edited comment and the open menu, editing, delete dialog, highlighted permalink. `ux` reviews.
- `qa` review: migration, contract, rights and tenant 404s.
