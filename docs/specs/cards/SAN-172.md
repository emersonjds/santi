# SAN-172 — Notifications: a bell for mentions, assignments and comments

Owner (2026-10-19): when someone @mentions a teammate, that person sees it as soon as they open
santi — a bell in the top bar, no email (SAN-68 waits for a domain). Mentions are stored as
`[@Name](mention:<user_id>)` (D50); today nobody is told.

## Decisions

| # | Question | Winner |
|---|---|---|
| 1 | Events (v1) | `mention`: you were @mentioned in a comment or a description. `assigned`: an issue was assigned to you. `comment`: someone commented on an issue you reported or are assigned to. Never notify the person who made the change. One event per recipient per change: a mention wins over `comment` for the same comment. |
| 2 | Mentions on edit | Only mentions added by the edit notify (the set of ids in the new text minus the old one), for comments and descriptions. Only project members count; unknown ids are ignored. |
| 3 | Data | Table `notification (id, recipient_id FK, actor_id FK, kind text check, project_id FK, issue_id FK cascade, comment_id FK cascade NULL, created_at, read_at NULL)`; indexes `(recipient_id, read_at, id DESC)` for the unread count, `(recipient_id, id DESC)` for the list, and `issue_id`, `comment_id`, `project_id`, `actor_id` for the cascades and account erasure. Written in the same transaction as the change that causes it. |
| 4 | Visibility | A notification shows only while the recipient is still a member of its project and the project is not trashed (archived ones still show). Deleting the issue or comment deletes its notifications (cascade). Erasing an account deletes the notifications it received and those it caused. Rows older than 90 days are purged by the existing hourly job. |
| 5 | API | `GET /api/notifications?cursor=` (newest first, 50 per page, unread and read together, each with actor name, kind, project key, issue key + summary, comment id and a 140-char excerpt of the comment or description); `GET /api/notifications/unread-count` → `{ count }`; `POST /api/notifications/{id}/read`; `POST /api/notifications/read-all`. Only your own; another person's id is 404. |
| 6 | Bell | In the top bar next to the account button: a bell icon button (44 px) "Notifications", with a badge showing the unread count (9+ above 9) and `aria-label` "Notifications, N unread". Count polled every 60 s and on window focus (no websocket yet); polling stops while the tab is hidden. |
| 7 | Panel | Popover from the bell (sheet from the bottom at 375 px): title "Notifications", "Mark all as read" when anything is unread, then the list: actor avatar, a line "Ana mentioned you on SAN-12" / "Ana assigned SAN-12 to you" / "Ana commented on SAN-12", the issue summary, the excerpt, relative time; unread rows have a dot and stronger text. Click (or Enter) opens the issue, scrolled to the comment when there is one, and marks it read. "Load more" at the end. Empty: "You're all caught up." Error: "Notifications did not load." with Try again. |
| 8 | For you page | Unread mentions show at the top of the home "For you" page as a short list (max 5) linking to the panel's items; nothing when there are none. |
| 9 | CLI / MCP | `santi notifications` (list, `--unread`, `--json`), `santi notifications read <id>`, `santi notifications read --all`. MCP `list_notifications` (read-only; excerpts are untrusted text) and `mark_notifications_read { ids? , all? }`. |
| 10 | Precedence (qa) | One event per person per change: `assigned` > `mention` > `comment`. Being made the assignee is the stronger fact, so a person assigned and mentioned in the same create or edit gets only `assigned`. |
| 11 | Excerpt (qa) | Mention tokens (D50, escaped names included) become `@Name` before the 140-character cut, so a token is never split; then every `\x` escape reads `x` (simple unescape, the excerpt is a preview). |
| 12 | Kind filter (qa) | `GET /api/notifications` takes an optional `kind` (`mention`, `assigned`, `comment`); an unknown kind is 400 like the other enum filters. For you asks `unread=true&kind=mention&limit=5` instead of filtering a page on the client. |
| 13 | CLI text (qa) | `santi notifications` strips control, zero-width and bidi characters from the actor name, summary and excerpt (the same filter as saved attachment names). |
| 14 | CLI paging (qa) | `santi notifications --cursor <id> --limit <n>`; when more exist the last line reads "… older notifications not shown; see them with --cursor <id>". |

## Acceptance

- Ana mentions Bo in a comment → Bo's count goes up within 60 s or on focus; the panel shows it; clicking opens the issue at the comment and the count drops.
- Ana assigns Bo → `assigned`. Ana comments on Bo's issue → `comment`. Ana mentioning herself or assigning herself → nothing.
- Editing a comment to add a mention notifies only the new person.
- Bo removed from the project → its notifications stop showing; trash hides them; issue delete removes them.
- Another account cannot read or mark Bo's notifications (404).
- qa review (contract, tenant).
